NL2SQL Agentic System

Problem

Business teams could not query BigQuery themselves, so every KPI question became an ad-hoc ticket and analysts spent their weeks answering them.

Approach

A multi-agent system on Vertex AI Agent Engine, built with Google ADK. A semantic router sends each question to the right specialist. SQL generation is M-Schema aware, so the agent cannot invent tables that do not exist, and a grounding guardrail validates every number against live BigQuery results before it reaches a user. When confidence is low, the agent abstains instead of guessing.

questionplain language, multi-turn
semantic routerpicks the specialist agent
SQL agentM-Schema aware generation
grounding guardrailvalidates against live BigQuery
answer, or abstainno unverified numbers

Result

In production at Maxis today, answering telecom KPI questions for non-technical users. The grounding loop eliminated hallucinated figures: every number shown has been checked against the warehouse that produced it. I own the full LLMOps loop, from containerized Cloud Run deploys to versioned prompts, reliability and cost monitoring.

NL-to-DAX Agent, and the harness that attacks it

Problem

An agent can pass every automated test and still fail real users. Happy-path suites reward memorizing the demo.

Approach

I built a natural-language-to-DAX agent for Power BI, then built an adversarial QA harness to break it: probes that feed the agent inputs the test oracle never covered, score the answers, and turn every failure into a permanent regression case.

Result

This is now how I evaluate every agent I ship. A green suite is necessary. It is never sufficient.

Self-Improving Agent Architecture

Problem

Agent Engine sessions are stateless. Anything an agent learns dies with the conversation, and the naive fix adds a database read to every single turn.

Approach

Learned policy lives in Firestore, separated cleanly from per-user conversational memory. In-memory caching plus realtime listeners mean agents pick up cross-user policy updates instantly, without a per-turn latency cost. What one conversation teaches, every future conversation knows.

policy storeFirestore. cross-user, cached, realtime listeners
session memoryper-user, stateless sessions
agent turnreads both at zero added latency, writes learned policy back

Job Agent, a pipeline that cannot lie about you

Problem

Most LLM resume tools happily invent experience. An agent that writes about you has to be incapable of lying.

Approach

Every generated bullet must cite a fact stored in a Supabase knowledge base, and a verification pass rejects any claim without a source before rendering. Around 190 test files behind it, Airflow for scheduled job discovery, Playwright for assisted autofill.
